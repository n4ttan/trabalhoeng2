1. Introdução
O sistema Morada Residências tem como objetivo facilitar o gerenciamento de condomínios residenciais, oferecendo recursos para o cadastro de usuários, controle de acesso, aprovação de moradores, gerenciamento de condomínios e blocos, comunicação entre usuários e administração de atividades condominiais.

A aplicação possui uma interface web desenvolvida com React e Vite, além de um servidor construído com Node.js e Express. O sistema utiliza banco de dados MySQL para armazenar as informações e mecanismos de autenticação baseados em JWT para controlar o acesso dos usuários.

O sistema também possui funcionalidades relacionadas à validação de e-mail, aprovação de cadastros, solicitações para atuação como síndico, gerenciamento de notificações, reuniões, reservas de espaços comuns e controle de boletos condominiais.

Além disso, utiliza Socket.IO para permitir comunicação em tempo real e a plataforma Brevo para o envio de mensagens de validação de e-mail.
1.1 Visão geral do documento
Este documento apresenta os requisitos funcionais e não funcionais do sistema Morada Residências, descrevendo suas principais funcionalidades, seus comportamentos esperados e as condições necessárias para sua utilização.

O documento está organizado em seções que apresentam a introdução, a descrição geral do sistema, os requisitos funcionais organizados em casos de uso, os requisitos não funcionais e as referências utilizadas.
1.2 Convenções, termos e abreviações
RF: Requisito Funcional.

RNF: Requisito Não Funcional.

Usuário: Pessoa cadastrada ou que deseja realizar cadastro no sistema.

Morador: Usuário vinculado a um condomínio residencial.

Síndico: Usuário responsável por atividades administrativas do condomínio, conforme as permissões previstas no sistema.

Administrador: Usuário responsável por operações administrativas da plataforma.

Condomínio: Conjunto residencial administrado por meio do sistema.

Bloco: Divisão ou agrupamento de unidades pertencente a um condomínio.

Unidade: Apartamento ou residência vinculada a um morador.

Boleto: Documento utilizado para representar uma cobrança condominial.

Autenticação: Processo de verificação da identidade de um usuário.

JWT: JSON Web Token, utilizado para representar informações de autenticação.

API: Interface que permite a comunicação entre diferentes partes do sistema.

MySQL: Sistema gerenciador de banco de dados utilizado pela aplicação.

Socket.IO: Tecnologia utilizada para permitir comunicação em tempo real entre cliente e servidor.

Código de verificação: Código enviado ao e-mail do usuário para confirmar o endereço eletrônico.
1.2.1 Identificação dos requisitos
Os requisitos são identificados por siglas e números sequenciais.

RF01, RF02, RF03...: identificam os requisitos funcionais.

RNF01, RNF02, RNF03...: identificam os requisitos não funcionais.

Cada requisito descreve uma funcionalidade ou característica esperada do sistema.
1.2.2 Prioridades dos requisitos
Os requisitos são classificados conforme sua importância para o funcionamento do sistema.

Essencial: requisito necessário para as principais operações do sistema.

Importante: requisito que contribui significativamente para o funcionamento e a utilização da aplicação.

Desejável: requisito complementar, cuja ausência não impede necessariamente o funcionamento das funcionalidades principais.

2. Descrição geral do sistema
2.1 Abrangência e sistemas relacionados
O sistema Morada Residências contempla as seguintes áreas:
- Cadastro de usuários.
- Validação de endereço de e-mail por código.
- Autenticação de usuários.
- Controle da situação dos cadastros.
- Aprovação ou rejeição de cadastros por usuários com função administrativa.
- Solicitação para atuar como síndico.
- Consulta e análise de solicitações de síndico.
- Cadastro, consulta e remoção de condomínios.
- Cadastro e gerenciamento de blocos.
- Associação de moradores a blocos e unidades.
- Associação de síndicos a condomínios e blocos.
- Gerenciamento de notificações.
- Registro de leitura de notificações.
- Agendamento e consulta de reuniões.
- Gerenciamento de reservas de churrasqueiras.
- Gerenciamento de reservas de salões de festas.
- Emissão e consulta de boletos.
- Geração de boletos individuais e em lote.
- Emissão de segunda via de boletos.
- Simulação de pagamento de boletos.
- Consulta da situação financeira dos condomínios.
- Identificação de moradores com boletos pendentes.
- Comunicação em tempo real.
O sistema utiliza tecnologias externas para apoiar seu funcionamento, incluindo MySQL para o banco de dados e a API de envio de e-mails Brevo para o envio de mensagens de validação.

A aplicação também utiliza bibliotecas e serviços de apoio à autenticação, à comunicação entre cliente e servidor e à atualização de informações em tempo real.

■ Essencial          ◻ Importante          ◻ Desejável

Saídas e pós-condição:

[RF02] Validação de endereço de e-mail
Descrição do caso de uso: O sistema deve permitir que o usuário confirme seu endereço de e-mail por meio de um código de verificação enviado ao endereço informado no cadastro.

Prioridade:

■ Essencial          ◻ Importante          ◻ Desejável

Entradas e pré-condições:
- O usuário deve ter iniciado o processo de cadastro.
- O sistema deve ter disponibilizado o envio do código de verificação.
- O usuário deve informar o código recebido por e-mail.
Saídas e pós-condição:
- O sistema verifica o código informado.
- Quando a validação é bem-sucedida, o cadastro pode avançar para a próxima etapa prevista no fluxo.
- Quando o código é inválido ou expirado, o sistema deve impedir a validação por aquele código.
- O código de verificação possui prazo de validade de 15 minutos.
- O fluxo estabelece um limite de cinco tentativas incorretas e um intervalo de 60 segundos para permitir um novo envio do código.
[RF03] Reenvio do código de verificação

Saídas e pós-condição:
- O sistema processa a solicitação de reenvio.
