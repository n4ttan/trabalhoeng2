1. USUÁRIOS (USUARIOS)
============================================================

USUARIOS (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nome VARCHAR(255) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    senha VARCHAR(255) NOT NULL,
    perfil ENUM(
        'ADMIN_PLATAFORMA',
        'USUARIO',
        'CANDIDATO',
        'SINDICO',
        'MORADOR',
        'ADMIN'
    ) NOT NULL,
    id_condominio INT NULL,
    id_bloco INT NULL,
    bloco VARCHAR(100) NULL,
    unidade VARCHAR(50) NULL,
    status_cadastro ENUM(
        'AGUARDANDO_EMAIL',
        'PENDENTE_APROVACAO',
        'APROVADO',
        'REJEITADO'
    ) DEFAULT 'AGUARDANDO_EMAIL',
    token_validacao VARCHAR(255) NULL,
    token_expira_em DATETIME NULL,
    tentativas_validacao INT NOT NULL DEFAULT 0,

    FOREIGN KEY (id_condominio)
        REFERENCES CONDOMINIOS(id)
        ON DELETE SET NULL,

    FOREIGN KEY (id_bloco)
        REFERENCES BLOCOS(id)
        ON DELETE SET NULL
)

7. NOTIFICAÇÕES (NOTIFICACOES)
============================================================

NOTIFICACOES (
    id INT PRIMARY KEY AUTO_INCREMENT,
    titulo VARCHAR(150) NOT NULL,
    mensagem TEXT NOT NULL,

        REFERENCES USUARIOS(id)
        ON DELETE SET NULL

8. DESTINATÁRIOS DE NOTIFICAÇÕES
   (NOTIFICACAO_DESTINATARIOS)
============================================================

NOTIFICACAO_DESTINATARIOS (
    notificacao_id INT NOT NULL,
    usuario_id INT NOT NULL,
    lida_em TIMESTAMP NULL DEFAULT NULL,

    PRIMARY KEY (notificacao_id, usuario_id),

    FOREIGN KEY (notificacao_id)
        REFERENCES NOTIFICACOES(id)
        ON DELETE CASCADE,

    FOREIGN KEY (usuario_id)
        REFERENCES USUARIOS(id)
        ON DELETE CASCADE
)

OBSERVAÇÃO:
A tabela NOTIFICACAO_DESTINATARIOS possui uma chave primária
composta pelos atributos notificacao_id e usuario_id.

Essa tabela associativa implementa o relacionamento N:M entre
USUARIOS e NOTIFICACOES, permitindo que uma notificação seja
enviada para vários usuários e que um usuário receba várias
notificações.

O atributo lida_em registra a data e o horário em que o usuário
visualizou a notificação. Caso ainda não tenha sido lida,
o valor permanece NULL.

        'PENDENTE',
        'CONFIRMADA',

    ) NOT NULL DEFAULT 'CONFIRMADA'
)

OBSERVAÇÃO:
Os atributos id_usuario e id_condominio identificam o usuário
responsável pela reserva e o condomínio relacionado.

No código SQL atual, esses atributos não possuem restrições
FOREIGN KEY declaradas.

14. RESUMO DAS CHAVES ESTRANGEIRAS (FK)
============================================================

USUARIOS:
- id_condominio -> CONDOMINIOS(id)
- id_bloco -> BLOCOS(id)

BLOCOS:
- id_condominio -> CONDOMINIOS(id)

GESTORES_CONDOMINIOS:
- usuario_id -> USUARIOS(id)
- condominio_id -> CONDOMINIOS(id)
- bloco_id -> BLOCOS(id)

PEDIDOS_SINDICO:
- usuario_id -> USUARIOS(id)
- condominio_id -> CONDOMINIOS(id)

NOTIFICACOES:
- condominio_id -> CONDOMINIOS(id)
- criado_por -> USUARIOS(id)

NOTIFICACAO_DESTINATARIOS:
- notificacao_id -> NOTIFICACOES(id)
- usuario_id -> USUARIOS(id)

BOLETOS:
- id_condominio -> CONDOMINIOS(id)
- id_usuario -> USUARIOS(id)

OBSERVAÇÃO:
As tabelas RESERVAS_CHURRASQUEIRA, RESERVAS_SALAO e REUNIOES
possuem atributos que identificam usuários ou condomínios,
mas esses atributos não foram definidos como chaves estrangeiras
no código SQL atual.

O atributo sindico_responsavel da tabela CONDOMINIOS também
não possui uma restrição FOREIGN KEY declarada.

16. OBSERVAÇÕES SOBRE A ESTRUTURA DO BANCO DE DADOS
============================================================

1. A tabela NOTIFICACAO_DESTINATARIOS é responsável por
   implementar o relacionamento muitos-para-muitos (N:M)
   entre usuários e notificações.

2. A tabela BOLETOS possui relacionamentos com CONDOMINIOS
   e USUARIOS por meio de chaves estrangeiras.

3. As tabelas RESERVAS_CHURRASQUEIRA e RESERVAS_SALAO
   armazenam informações de reservas de espaços comuns.

4. A tabela REUNIOES armazena informações sobre reuniões
   vinculadas a condomínios.

5. As tabelas de reservas e reuniões possuem campos de
   identificação de usuários ou condomínios, mas não possuem
   FOREIGN KEY declarada no SQL atual.

6. A tabela CONDOMINIOS possui o atributo sindico_responsavel,
   mas não existe uma FOREIGN KEY declarada para esse campo.

7. As tabelas MENSAGENS e NOTIFICACOES possuem finalidades
   distintas. MENSAGENS armazena textos simples, enquanto
   NOTIFICACOES gerencia avisos e comunicados destinados
   aos usuários.

8. O arquivo 4_boletos.sql apresenta novamente a definição
   da tabela BOLETOS. A estrutura dessa tabela também está
   presente no arquivo 2_schema.sql.
